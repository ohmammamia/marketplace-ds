# Dataset

## What the pipelines expect (schema)
| table | key | columns |
|---|---|---|
| providers | provider_id | home_zone, coverage (comma list), job_type {manual,auto,both}, price_per_hour, tier {accredited,apprentice}, years_experience, gender, language, weekday_day/weekday_eve/weekend (0/1), weekly_lead_capacity, rating, credit_balance, joined_at |
| leads | lead_id | created_at, zone, job_type, weekday_day/eve/weekend, budget_max, urgency {none,deadline,emergency}, hours_wanted, pref_gender, language, is_returning, source |
| offers | (lead_id, provider_id) | offered_at, rank_shown, purchased, contacted, converted, lead_price_gbp |

Full validation rules: `src/data.py` (`PROVIDER_SCHEMA`, `LEAD_SCHEMA`, `OFFER_SCHEMA`).

## What is in this repository
**Synthetic demo data only** (`data/synthetic/`, generated by `common/synthetic.py`).
It reproduces the schema, the realistic data-quality problems (duplicate registrations,
inconsistent categories, missing prices/ratings, unknown zones, orphan offer rows)
and a latent outcome process, so that every pipeline can be run and reviewed end to end.

No row is a real customer, provider, lead or message. Latent generator variables
(e.g. provider responsiveness) are never exported.

## What is NOT in this repository
Production the marketplace data, identifiers, message text or aggregates from which
records could be reconstructed. The analysis was developed against authorised internal
data with the same schema; the public repository carries code, schemas, validation
logic, feature definitions, configuration, fixtures and documentation only.

## Known quality issues (synthetic, mirroring production)
| issue | handling |
|---|---|
| duplicate provider registrations | exact match on stable attributes, keep earliest id (D1) |
| job_type casing | normalised to lower case |
| ~5% missing rating, ~3% missing price | imputed at feature time with an explicit `price_missing` flag |
| ~2% leads with unknown zone | dropped: no candidate generation possible; flagged for product fix |
| orphan offer rows | dropped after referential-integrity check |
| sparse provider history / new providers | empirical-Bayes shrinkage (prior_n = 10) |
| temporal leakage | history features computed strictly before `created_at`; temporal train/test split |
